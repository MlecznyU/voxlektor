# voxlektor: design

**Status:** accepted 2026-11-10 · **Date:** 2026-11-10 · **Target repo:** `voxlektor` (separate repository on GitHub)


---

## 1. Intent

A local tool that reads **any text** aloud in a natural voice, in Polish and English. It is meant to be **independent of Claude Code**: you use it from the terminal, the clipboard or a file, and in the future other tools (e.g. the dialogue-box plugin) can call it through a stable API.

Uses: listening to notes and documentation, "home-made audiobooks" from book excerpts, and in the future reading Claude's replies aloud.

**Why now:** the current voices (Edge neural, Mac `say`) sound artificial. Measurements in `tts-lab` showed that a local open-source model gives much better quality at an acceptable speed.

## 2. Goals, non-goals, anti-goals

**Goals**
- Read any PL/EN text, including developer mash-up ("zmergowałem brancha" ("I merged the branch")), locally, offline once the model is downloaded.
- Speech starts in conversation mode in ≤ ~3 s with the model loaded, with no gaps between paragraphs.
- One-command install and a step-by-step configurator, no code reading required.
- Engine and platform swappable without rewriting the core.

**Non-goals (v1)**
- Integration with dialogue-box **inside voxlektor itself**. The tool knows nothing about the plugin; it is the plugin that gets a new engine which talks to voxlektor (phase 2, §11).
- Extracting text from PDF/EPUB, GUI, menu bar app.
- Languages other than PL and EN.
- Platforms other than macOS on Apple Silicon.
- Speech recognition (STT).

**Anti-goals (failure, even if it works)**
- The tool loads the computer when it is not reading anything.
- It leaves temporary files or junk on disk.
- Changing the model in the future requires recreating voices.
- It requires fiddling with environment variables or the shell profile.
- It sends text anywhere off the computer.

## 3. Constraints

- **v1 platform:** macOS 14+ on Apple Silicon; min. 8 GB RAM (16 GB recommended); ~4 GB disk. The README states this explicitly.
- **Open-source engines only.**
- The target model runs locally; the network is needed only to download models and to install.
- The user's local Hugging Face token is invalid (401 on public repos). Downloading public models must work without a token (`HF_HUB_DISABLE_IMPLICIT_TOKEN=1` or equivalent).

## 4. Decisions (agreed in conversation)

| Area | Decision |
|---|---|
| Name | **voxlektor**, command alias **`vxl`** (`lektor` is taken on PyPI). |
| Default engine | **OmniVoice** via `mlx-audio` (`mlx-community/OmniVoice-bf16`), `num_steps=16`. |
| Voice | **Zero-shot cloning** from samples generated by VoxCPM2. The user judged that the clone sounds closer to VoxCPM2 than plain OmniVoice. |
| Voices in the repo | 7 ready-made: `v0-default`, `f1-warm`, `f2-narrator`, `f3-bright`, `m1-calm`, `m2-narrator`, `m3-casual`. All shipped; setup only asks for the default. |
| Optional engines | **VoxCPM2** (`mlx-community/VoxCPM2-8bit`) downloaded on demand: designing new voices from a description and top-quality audiobooks. |
| Operating mode | **Background service + thin CLI**, with the option to work without the service (see §6). |
| Keep-warm | `idle_timeout` configurable at 3 levels + manual `unload` / `stop`. |
| Audio | **No temporary files.** Written to disk only on demand (`--out`). |
| Configuration | TOML file; environment variables only as an optional override. |
| Distribution | `install.sh` (curl \| sh) → `uv tool install` from GitHub → configurator. |
| Speed-up | Tempo set in the player (`rate`), generation unchanged. The user listens faster than 1×. |

**My decisions (to check when reading):**
- Default `idle_timeout = 10m`.
- The first command starts the service by itself (`service.autostart = true`).
- Autostart at login (launchd) **off** by default, can be enabled in setup.
- Undo history: last 20 paragraphs in RAM.
- Control via a Unix socket with JSON, no network port.
- `vxl "…"` **returns immediately** after adding the text to the queue. `vxl --wait "…"` waits until reading finishes; Ctrl+C in `--wait` interrupts reading. Protocol: request/response + optional event subscription (`progress`, `done`, `error`), which `--wait` uses.
- **VoxCPM2 does not play live** (0.43× realtime). It is used only for rendering to a file: `vxl --engine voxcpm2 --out file.wav …`. Rendering is a **separate one-off process**, not a service job; the OmniVoice service runs alongside (~10 GB RAM in total; on machines < 16 GB `doctor`/CLI warns).
- `--out` **replaces** playback by default; `--out … --play` does both.

## 5. Features

### 5.1 Reading
```bash
vxl "any text"                 # argument
pbpaste | vxl                  # stdin
vxl -f notes.md              # text / markdown file
vxl --voice m2 --rate 1.25 --lang en "…"   # one-off overrides
vxl --out chapter.wav -f chapter.txt     # write instead of playing (--play: both)
vxl --engine voxcpm2 --out chapter.wav -f chapter.txt   # top-quality render, separate process
```
- Text is split into paragraphs (blank line), and overly long paragraphs into sentences, with a chunk length limit tuned to the model.
- **Look-ahead generation:** paragraph N+1 is generated while N plays. With OmniVoice-16 (~3× realtime) there are no gaps.
- Language: `auto` (default), `pl` or `en`. In `auto` mode the language is detected per paragraph. PL/EN mixed within one sentence goes as the dominant language (checked on the palette: the model handles "zmergowałem brancha").
- Markdown with `-f`: markup (`#`, `*`, code blocks) stripped before reading; code blocks skipped or announced ("code block skipped"). I leave the choice to the builder.
- Further `vxl "…"` calls during reading **are appended to the queue** (the `--now` flag interrupts and reads immediately).

### 5.2 Playback control
```bash
vxl pause | resume | skip | back | stop-reading
vxl queue                      # what is playing, what is waiting
```
- `back` goes back one paragraph (from the RAM history). `skip` moves to the next one.
- Works from any terminal, because the service holds the state.

### 5.3 Service and keep-warm
```bash
vxl serve [--idle 30m|0]       # manual start (normally starts by itself)
vxl idle 1h                    # change on the fly, no restart
vxl unload                     # free the model from RAM, the service stays (~50 MB)
vxl stop                       # shut down the service
vxl status                     # state (OFF/COLD/WARM), RAM, engine, voice, time until unload
```
- Cycle: `OFF → WARM` (first reading / serve) · `WARM → COLD` (`idle_timeout` elapsed or `unload`) · `COLD → WARM` (next reading, +3–4 s) · `* → OFF` (`stop`).
- The idle timer counts from the **end** of the last reading. Pause suspends it. `idle_timeout = 0` means "never unload".
- At most **one** engine in RAM at any time.

### 5.4 Voices
```bash
vxl voices                     # list
vxl voices play f2-narrator    # play a sample
vxl config voice f2-narrator   # default
vxl voices add myvoice --from recording.wav --text "recording transcript"   # custom clone
vxl voices design "voice description" --name x   # requires the voxcpm2 engine
vxl voices remove x
```
- Voice = `ref.wav` + `ref.txt` (source of truth, engine-independent) + `cache/<engine>.npz` (encoded prompt, reproducible).
- Changing the engine invalidates only the cache; the voices stay.
- On the first use of a voice with a given engine, the prompt is encoded and cached. **Goal:** start ≈ OmniVoice without a clone (~3 s). A measurement with encoding on every call gave 5.8 s.

### 5.5 Engines (downloaded on demand)
```bash
vxl engines                    # installed / available, size
vxl engines add voxcpm2
vxl engines remove voxcpm2     # voices stay
vxl config engine omnivoice
```

### 5.6 Installation, configurator, diagnostics
```bash
curl -fsSL https://raw.githubusercontent.com/MlecznyU/voxlektor/main/install.sh | sh
vxl setup            # the whole configurator
vxl setup voice      # a single step
vxl doctor           # what is wrong + how to fix it
vxl uninstall        # removes the service, launchd, config (asks), model cache (asks)
```
`install.sh`: checks macOS + Apple Silicon → installs `uv` if missing → `uv tool install git+https://github.com/MlecznyU/voxlektor` (commands `voxlektor` and `vxl` in `~/.local/bin`) → runs `vxl setup`.

`setup` steps: 1) hardware (chip, RAM, warnings) · 2) OmniVoice download with a progress bar · 3) voice selection with preview (arrow keys) · 4) default language, tempo, `idle_timeout` · 5) autostart at login (default: no) · 6) test sentence.

`doctor` checks, among other things: platform, free RAM and disk, presence of models, service and socket state, audio device, the HF token problem, directory permissions.

## 6. Architecture

> **Superseded by `docs/architecture.md`** (adopted 2026-11-10). The sketch below is kept for history; wherever it differs (Engine SPI returns an `Iterator`, the voice cache belongs to the `app` layer, file `cache/<engine>-<rev8>-p<format>.bin`, LOADING/UNLOADING states, request `id` and error codes in the protocol), the architecture document is binding.

```
vxl (CLI) ──► service running? ──yes──► Unix socket (JSON) ──► Service
                 │                                        ├─ text and audio queue, history
                 no                                       ├─ keep-warm / idle timer
                 ├─ service.autostart=true → start the service and send
                 └─ service.autostart=false → one-shot in-process mode
                                                          ├─ Engine (interface)
                                                          └─ Player (sounddevice)
```

- **One-shot mode** (no service): loads the model, reads, exits the process. No control from other terminals. This is a deliberate user choice in the configuration.
- **Socket:** `~/Library/Application Support/voxlektor/voxlektor.sock` (via the Platform layer), permissions `0600`, directory `0700`. No TCP listener.
- **Protocol:** one JSON message per line. Commands: `speak`, `pause`, `resume`, `skip`, `back`, `stop_reading`, `queue`, `status`, `idle`, `unload`, `shutdown`. Versioned (`"v": 1`), because other tools (dialogue-box) will use it in the future. Documented in `docs/protocol.md`.

### Engine interface
```python
class Engine(Protocol):
    name: str

    def load(self) -> None: ...
    def unload(self) -> None: ...
    def prepare_voice(self, ref_wav: Path, ref_text: str) -> VoiceCache: ...
    def synthesize(self, text: str, lang: str, voice: VoiceCache) -> Iterator[np.ndarray]: ...

    sample_rate: int
```
v1: `omnivoice-mlx` (default), `voxcpm2-mlx` (optional, for `voices design` and quality mode). A port to Linux/NVIDIA = a new backend (OmniVoice has its original in PyTorch, k2-fsa).

### Platform layer
Paths (config, data, socket), autostart (launchd on macOS), hardware check. v1 macOS only; the rest raises a readable "platform not supported yet" error.

## 7. Data on disk

| What | Where (macOS) | Persistent |
|---|---|---|
| Configuration | `~/.config/voxlektor/config.toml` | ✅ |
| Voices | `~/.config/voxlektor/voices/<name>/{ref.wav,ref.txt,cache/}` | ✅, a few hundred KB/voice |
| Models | standard Hugging Face cache | ✅, managed by `engines` |
| Socket, PID, log | `~/Library/Application Support/voxlektor/` | log rotated, small |
| Reading audio | **nowhere**, RAM only | ❌ |
| `--out` | user path | ✅, on demand |

Settings precedence: **flag > `VOXLEKTOR_*` variable > config.toml > defaults**.

## 8. Stack

- Python 3.12, `uv` (project + `uv tool install`).
- `mlx-audio` (pinned version; the one from 2026-11-09 worked in tts-lab), `mlx`.
- `sounddevice` (PortAudio), `numpy`, `soundfile`.
- CLI: `typer` (already among mlx-audio's dependencies).
- TOML: `tomllib` (read) + `tomli-w` (write).
- Language detection: a lightweight offline library or a heuristic (PL diacritics + a dictionary of common words). Builder's choice.
- Tempo without changing voice pitch: library choice left to the builder (time-stretch on chunks before sending to `sounddevice`).

## 9. Performance (measured in tts-lab, M4 / 32 GB)

| Variant | 1st paragraph start | Speed | RAM |
|---|---|---|---|
| OmniVoice-16 | 2.7 s | ~3× realtime | 3.1 GB |
| OmniVoice-16 + clone (no prompt cache) | 5.8 s | 1.4–1.8× | ~3.1 GB |
| VoxCPM2 8-bit (best quality) | 13.7 s | 0.43× | 6.4 GB |
| Model load + first call | 3–4 s | | |

Idle with the model in RAM: 0% CPU/GPU. Generation: GPU in bursts for ~1/3 of the listening time. Power draw and temperature **not measured**.

## 10. Security (requirements)

- Text never reaches a shell or `subprocess` via interpolation.
- Socket local only, `0600`; the service rejects messages with an unknown version, oversized messages and invalid JSON.
- Models downloaded only from a list of known repositories with **pinned revisions**.
- `install.sh`: `set -euo pipefail`, no `sudo`, prints what it does; installs from a tag/version, not from a branch.
- launchd plist only in `~/Library/LaunchAgents`, no administrator privileges.
- `voices add` checks the recording's format and length (a limit, e.g. 30 s).

## 11. Process and phases

Quality/speed trade-offs (clone vs start vs gaps at sped-up tempo) **are settled empirically**, in real use, not up front. That is why we build in phases.

**Phase 1: basic version (MVP)**
- Service + CLI `vxl` / `voxlektor`, protocol v1 over the socket (`speak`, `pause`, `resume`, `skip`, `back`, `stop_reading`, `status`, `idle`, `unload`, `shutdown`).
- Input: argument, stdin, `-f` (plain text).
- OmniVoice-16 with a clone and **prompt cache**; 7 voices from the palette; `--voice`, `--lang`, `--rate`.
- Keep-warm: `idle_timeout`, `unload`, `stop`, service autostart.
- `config.toml` + flags; installation via `uv tool install` from a local directory/git.
- Look-ahead generation + measurement: start, speed, gaps at `rate` 1.0 / 1.25 / 1.5.

**Phase 2: test with dialogue-box**
- A new engine in dialogue-box that sends paragraphs to the voxlektor service over the socket (alongside Edge and Mac). This is **a change in the plugin, made on a separate branch**, only after phase 1.
- Evaluation in a real conversation: whether start, gaps and sound are right. Based on that, a decision on the trade-offs from the reviewer's question 1.

**Phase 3: the rest of this document**
- `install.sh`, full `setup` with preview, `doctor`, `uninstall`, `engines add/remove`, `voices add/design/remove`, VoxCPM2 render `--out`, markdown in `-f`, `--wait`, `queue`, launchd.

**Reviews:** after phase 1 and after phase 3, two independent subagent reviews: security (installer, socket, model downloads, file input) and bugs/correctness (queue, service states, keep-warm races, audio handling). Push to the public repo only after review.

## 12. Left to the builder

- Choice of library for language detection and for time-stretch.
- Exact text chunk length limit for OmniVoice.
- Log format, rotation.
- Handling of code blocks in markdown (skip or announce).
- Module structure within the package.
